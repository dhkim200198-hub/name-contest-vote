# 사내 이름 공모전 투표 시스템

로그인 없이 **링크 + 1회용 코드**로 참여하는 독립형 투표 사이트입니다.
외부 DB·외부 계정 없이 Node.js 하나로 동작하고, 투표 기록은 `data/db.json` 파일에 저장됩니다.

## 구성

| 경로        | 용도                                                                       |
| ----------- | ------------------------------------------------------------------------ |
| `/`         | 투표 페이지 — 코드 입력 → 순위 선택 → 제출                                 |
| `/admin`    | 관리자 페이지 — 후보/설명 편집, 단계 진행, 배점 조정, 코드 발급, 집계     |
| `/results`  | 결과 페이지 — 마감 후(또는 관리자가 공개 설정 시) 집계 공개               |

## 진행 흐름

1. **후보 입력** — 공모전에 올릴 이름 **4개**(기본, 준비 단계에서 개수 조정 가능)를 관리자 `후보` 탭에 입력.
   각 후보에 유형(순수한글/한자), 영문 표기, 상표 검색 결과, 그리고 **설명 칸**(대표님이 "어떤 시스템/의미인지" 작성)을 채웁니다.
   여기서 저장하면 투표 페이지에 바로 반영됩니다. 이름이 비어 있으면 투표 후보에서 자동 제외됩니다.
2. **1차 코드 발급 → 1차 투표** — `투표 코드` 탭에서 투표 인원수(예: 19)만큼 생성해 1인 1개씩 배포 →
   `설정`에서 단계를 `1차 투표 진행 중` 으로. 투표자는 이름 4개를 **순위대로** 선택 → 순위별 **60·30·10·0점**(조정 가능).
3. **1차 마감 → 2차 코드 발급 → 2차 투표** — 같은 이름 4개를 대상으로 다시 투표.
   투표자는 **순위대로** 선택 → 순위별 **5·4·3·2·1점**(조정 가능).
4. **종합 집계** — 최종 순위 = (1차 점수 × 1차 배율) + (2차 점수 × 2차 배율). 배율 기본 1 : 1, `설정` 탭에서 조정.
   (1차 배점 합이 100, 2차가 최대 14이므로 두 라운드를 대등하게 보려면 1차 배율을 0.14 정도로 낮춥니다.)
5. **최종 발표** — 단계를 `최종 발표` 로 두면 결과 페이지 상단에 종합 1위 이름과 **상금 100만원 안내**가 표시됩니다.

> 두 라운드 모두 이름 4개 전체에 투표하며, 1차에서 후보를 탈락시키지 않습니다.
> 코드 수만큼만 투표가 가능하므로 총 투표수가 자연히 배포된 코드 수(예: 19표)로 제한됩니다.
> 한 번 사용한 코드는 재사용 불가. 실수로 잘못 진행했다면 `설정 → 위험 구역` 에서 라운드별 초기화가 가능합니다.

## 로컬 실행

```bash
npm install
# 관리자 비밀번호 지정 (미지정 시 임시값 admin1234 + 경고)
#   Windows PowerShell:  $env:ADMIN_PASSWORD="원하는비밀번호"
#   macOS/Linux:         export ADMIN_PASSWORD=원하는비밀번호
npm start
```

- 브라우저에서 `http://localhost:3000` (투표), `http://localhost:3000/admin` (관리자)
- 테스트: `npm test`

## 배포 (외부 접근)

> 클릭 단위 상세 절차는 **[DEPLOY.md](DEPLOY.md)** 참고. 요약:

투표 기록 파일(`db.json`)이 유지되도록 **재시작해도 파일이 남는(영구 디스크)** 호스팅을 쓰세요.
무료 티어(예: Render Free)는 일정 시간 미접속 시 잠들며 깨어날 때 파일이 초기화되어 투표가 사라질 수 있으니 주의.

- **Render (유료 Starter)** — `render.yaml` 포함. New → Blueprint 로 한 번에 배포. 자세히는 [DEPLOY.md](DEPLOY.md) 방법 A.
- **Fly.io (무료 한도)** — 볼륨 1개로 파일 유지. [DEPLOY.md](DEPLOY.md) 방법 B.
- **VPS / 사내 서버** — `Dockerfile` 포함. `docker run -p 3000:3000 -e ADMIN_PASSWORD=... -v $PWD/data:/app/data <image>` 또는 `pm2 start server.js` + Nginx(HTTPS).

### 환경변수

| 변수             | 기본값     | 설명                                            |
| ---------------- | ---------- | --------------------------------------------- |
| `ADMIN_PASSWORD` | `admin1234` | 관리자 페이지 비밀번호. **배포 전 반드시 변경** |
| `PORT`           | `3000`     | 서버 포트 (호스팅이 자동 주입하면 그대로 사용)  |
| `DATA_DIR`       | `./data`   | `db.json` 저장 폴더. 영구 디스크 경로로 지정    |

## 데이터 백업

`DATA_DIR/db.json` 파일 하나가 전부입니다. 투표 종료 후 이 파일을 복사해 두면 기록이 보존됩니다.

## 참고 / 한계

- 인증을 코드 기반으로만 두었기 때문에, 코드를 받은 사람이 타인에게 넘기면 대신 투표할 수 있습니다(사내 명예 규칙 전제).
- 세션 토큰은 서버 메모리에 보관 → 서버 재시작 시 관리자는 다시 로그인하면 됩니다(투표 데이터는 파일에 안전).
- HTTPS는 호스팅 업체(또는 앞단 Nginx)가 처리한다고 가정합니다.
