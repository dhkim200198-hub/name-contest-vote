# 사내 이름 공모전 투표 시스템

로그인·코드 없이 **링크만 열면 바로 참여**하는 독립형 사이트입니다.
**4개 항목**(제조업 서비스 단 OS / 온톨로지 계층 / 데이터·AI·워크플로 서비스 / 배포 버전 관리 Ops)의
이름을 각각 독립적으로 제안·투표·집계합니다.
Node.js 하나로 동작하며, 데이터는 로컬 JSON 파일(`DATA_DIR/db.json`) 또는
Upstash Redis(무료) 중 하나에 저장됩니다 — 배포 환경에 맞게 고릅니다 ([DEPLOY.md](DEPLOY.md)).

## 구성

| 경로       | 용도                                                                       |
| ---------- | ------------------------------------------------------------------------- |
| `/`        | 참여 페이지 — 항목 선택 → (준비 단계) 이름 제안 또는 (투표 단계) 1차/2차 투표 |
| `/admin`   | 관리자 페이지 — 항목별 설명 편집, 단계 진행, 후보 관리, 배점·인원 설정, 집계 |
| `/results` | 결과 페이지 — 항목별 탭, 마감 후(또는 공개 설정 시) 종합 순위 공개          |

## 진행 흐름 (항목마다 독립적으로 진행)

1. **준비 단계 · 이름 제안** — 직원 누구나 `/`에서 항목을 고르고, 설명 페이지를 먼저 확인한 뒤
   **본인 번호**를 입력해 이름을 제안합니다. 항목당 **최대 2개**(1개만 제출해도 무방)까지 제안할 수 있고,
   총 4항목이면 1인당 최대 8개까지 제안 가능합니다. 상표 중복 여부는 **제안자 본인이 미리 확인**합니다.
   관리자는 `항목` 탭의 후보 목록에서 스팸/중복 이름을 숨기거나 삭제할 수 있습니다.
2. **1차 투표** — 관리자가 해당 항목의 **예상 투표 인원**을 정하고 그 항목의 단계를 `1차 투표 진행 중` 으로 바꾸면
   시작됩니다. **어느 항목이든 1차가 시작되는 순간 전체 4항목의 이름 제안이 동시에 마감**됩니다.
   투표자는 **토큰 100점을 마음에 드는 이름 최대 5개에 0~100점 자유 배분**(합계 = 100). 토큰·최대 개수는 항목별로 조정 가능.
3. **1차 마감 → 2차 투표** — 같은 항목의 같은 이름들을 대상으로 다시 투표. **순위대로** 선택 → 순위별 **5·4·3·2·1점**(조정 가능).
4. **종합 집계** — 항목별 최종 순위 = (1차 점수 × 1차 배율) + (2차 점수 × 2차 배율). 배율 기본 1:1, 항목 탭에서 조정.
5. **최종 발표** — 항목 단계를 `최종 발표` 로 두면 결과 페이지 해당 탭 상단에 종합 1위 이름과 **상금 안내**가 표시됩니다.

> 두 라운드 모두 그 항목의 이름 전체에 투표하며, 1차에서 후보를 탈락시키지 않습니다.
> **투표 참여 방식**(전체 설정 탭)은 두 가지 — ① 본인 번호(1~N) 입력: 번호당 1회, 브라우저 무관 ② 번호 없이: 링크만 열면 투표, 같은 브라우저 재투표만 차단.
> 이름 제안은 이 설정과 무관하게 **항상 본인 번호**가 필요합니다(항목별 개수 제한을 서버가 추적하기 위함).
> 링크는 사내에만 공유하세요. 잘못 진행했다면 항목 탭의 `위험 구역` 에서 그 항목만 라운드별로 초기화할 수 있습니다.
> **참여 기간에 제한은 없습니다.** Render 무료 플랜은 15분 유휴 시 잠들지만 `.github/workflows/keepalive.yml`(10분마다 핑)이 깨어 있게 유지합니다.

## 로컬 실행

```bash
npm install
# 관리자 비밀번호 지정 (미지정 시 임시값 admin1234 + 경고)
#   Windows PowerShell:  $env:ADMIN_PASSWORD="원하는비밀번호"
#   macOS/Linux:         export ADMIN_PASSWORD=원하는비밀번호
npm start
```

- 브라우저에서 `http://localhost:3000` (투표), `http://localhost:3000/admin` (관리자)
- 테스트: `npm test`

## 배포 (외부 접근)

> 클릭 단위 상세 절차는 **[DEPLOY.md](DEPLOY.md)** 참고. 요약:

- **Render(무료) + Upstash Redis(무료)** ★추천 — 둘 다 카드 등록 없이 무료. 투표 기록은 Upstash 에 저장되어 서버가 잠들어도 보존됩니다. [DEPLOY.md](DEPLOY.md) 방법 A.
- **Render 유료(Starter)** — Upstash 없이 영구 디스크만으로. 월 $7. [DEPLOY.md](DEPLOY.md) 방법 B.
- **Fly.io / VPS / 사내 서버** — [DEPLOY.md](DEPLOY.md) 방법 C·D. `Dockerfile` 포함.

### 환경변수

| 변수                       | 기본값      | 설명                                                          |
| -------------------------- | ----------- | --------------------------------------------------------- |
| `ADMIN_PASSWORD`           | `admin1234` | 관리자 페이지 비밀번호. **배포 전 반드시 변경**              |
| `UPSTASH_REDIS_REST_URL`   | (없음)      | 있으면 투표 기록을 Upstash Redis 에 저장 (없으면 로컬 파일)  |
| `UPSTASH_REDIS_REST_TOKEN` | (없음)      | 위와 한 쌍                                                  |
| `PORT`                     | `3000`      | 서버 포트 (호스팅이 자동 주입하면 그대로 사용)               |
| `DATA_DIR`                 | `./data`    | 파일 저장 시 `db.json` 폴더 (Upstash 사용 시 무시)          |

## 데이터 백업

파일 저장이면 `DATA_DIR/db.json` 하나, Upstash 면 `name-contest-vote:db` 키 하나가 전부입니다.
투표 종료 후 관리자 `결과 · 집계` 화면을 캡처해 두거나 위 값을 복사해 두면 기록이 보존됩니다.

## 참고 / 한계

- 로그인·코드가 없어 링크를 받은 사람은 누구나 투표할 수 있습니다. 사내 채널에만 공유하는 것을 전제로 합니다.
- 중복 방지는 브라우저 저장(localStorage) 기반이라, 브라우저 데이터를 지우거나 다른 기기를 쓰면 재투표가 가능합니다. `예상 투표 인원` 자동 마감으로 총 표 수를 제한할 수 있습니다.
- 세션 토큰은 서버 메모리에 보관 → 서버 재시작 시 관리자는 다시 로그인하면 됩니다(투표 데이터는 파일에 안전).
- HTTPS는 호스팅 업체(또는 앞단 Nginx)가 처리한다고 가정합니다.
