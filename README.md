# 사내 이름 공모전 투표 시스템

로그인·코드 없이 **링크만 열면 바로 투표**하는 독립형 사이트입니다 (구글폼과 비슷).
Node.js 하나로 동작하며, 투표 기록은 로컬 JSON 파일(`DATA_DIR/db.json`) 또는
Upstash Redis(무료) 중 하나에 저장됩니다 — 배포 환경에 맞게 고릅니다 ([DEPLOY.md](DEPLOY.md)).

## 구성

| 경로       | 용도                                                                |
| ---------- | ---------------------------------------------------------------- |
| `/`        | 투표 페이지 — 링크 열기 → 1차: 토큰 배분 / 2차: 순위 선택 → 제출   |
| `/admin`   | 관리자 페이지 — 이름/설명 편집, 단계 진행, 배점·인원 설정, 집계    |
| `/results` | 결과 페이지 — 마감 후(또는 관리자가 공개 설정 시) 종합 순위 공개   |

## 진행 흐름

1. **후보 입력** — 공모전에 올릴 이름(기본 19칸, 준비 단계에서 2~30개로 조정 가능)을 관리자 `후보` 탭에 입력.
   각 후보에 유형(순수한글/한자), 영문 표기, 상표 검색 결과, 그리고 **설명 칸**(대표님이 "어떤 시스템/의미인지" 작성)을 채웁니다.
   저장하면 투표 페이지에 바로 반영됩니다. 이름이 비면 투표 후보에서 자동 제외됩니다.
2. **1차 투표** — `설정` 탭에서 **예상 투표 인원**(예: 19)을 정하고 단계를 `1차 투표 진행 중` 으로.
   투표자는 링크만 열어 **토큰 100점을 마음에 드는 이름 최대 5개에 0~100점 자유 배분**(합계 = 100). 토큰·최대 개수는 조정 가능. 예상 인원에 도달하면 자동 마감.
3. **1차 마감 → 2차 투표** — 같은 이름들을 대상으로 다시 투표. **순위대로** 선택 → 순위별 **5·4·3·2·1점**(조정 가능).
4. **종합 집계** — 최종 순위 = (1차 점수 × 1차 배율) + (2차 점수 × 2차 배율). 배율 기본 1 : 1, `설정` 탭에서 조정.
   (1차 총점이 100, 2차가 더 작으므로 두 라운드를 대등하게 보려면 1차 배율을 낮춥니다.)
5. **최종 발표** — 단계를 `최종 발표` 로 두면 결과 페이지 상단에 종합 1위 이름과 **상금 100만원 안내**가 표시됩니다.

> 두 라운드 모두 이름 전체에 투표하며, 1차에서 후보를 탈락시키지 않습니다.
> **투표 참여 방식**(설정 탭)은 두 가지 — ① 본인 번호(1~N) 입력: 번호당 1회, 브라우저 무관 ② 번호 없이: 링크만 열면 투표, 같은 브라우저 재투표만 차단.
> 링크는 사내에만 공유하세요. 잘못 진행했다면 `설정 → 위험 구역` 에서 라운드별 초기화가 가능합니다.
> **투표 기간에 제한은 없습니다** — 단계를 `1차 투표 진행 중`으로 열어 두면 며칠이든 아무 때나 투표됩니다. Render 무료 플랜은 15분 유휴 시 잠들지만 `.github/workflows/keepalive.yml`(10분마다 핑)이 깨어 있게 유지합니다.

## 로컬 실행

```bash
npm install
# 관리자 비밀번호 지정 (미지정 시 임시값 admin1234 + 경고)
#   Windows PowerShell:  $env:ADMIN_PASSWORD="원하는비밀번호"
#   macOS/Linux:         export ADMIN_PASSWORD=원하는비밀번호
npm start
```

- 브라우저에서 `http://localhost:3000` (투표), `http://localhost:3000/admin` (관리자)
- 테스트: `npm test`

- **Render 유료(Starter)** — Upstash 없이 영구 디스크만으로. 월 $7. [DEPLOY.md](DEPLOY.md) 방법 B.
- **Fly.io / VPS / 사내 서버** — [DEPLOY.md](DEPLOY.md) 방법 C·D. `Dockerfile` 포함.

### 환경변수

| 변수                       | 기본값      | 설명                                                          |
| -------------------------- | ----------- | --------------------------------------------------------- |
| `ADMIN_PASSWORD`           | `admin1234` | 관리자 페이지 비밀번호. **배포 전 반드시 변경**              |
| `UPSTASH_REDIS_REST_URL`   | (없음)      | 있으면 투표 기록을 Upstash Redis 에 저장 (없으면 로컬 파일)  |
| `UPSTASH_REDIS_REST_TOKEN` | (없음)      | 위와 한 쌍                                                  |
| `PORT`                     | `3000`      | 서버 포트 (호스팅이 자동 주입하면 그대로 사용)               |
| `DATA_DIR`                 | `./data`    | 파일 저장 시 `db.json` 폴더 (Upstash 사용 시 무시)          |

## 데이터 백업

파일 저장이면 `DATA_DIR/db.json` 하나, Upstash 면 `name-contest-vote:db` 키 하나가 전부입니다.
투표 종료 후 관리자 `결과 · 집계` 화면을 캡처해 두거나 위 값을 복사해 두면 기록이 보존됩니다.

## 참고 / 한계

- 로그인·코드가 없어 링크를 받은 사람은 누구나 투표할 수 있습니다. 사내 채널에만 공유하는 것을 전제로 합니다.
- 중복 방지는 브라우저 저장(localStorage) 기반이라, 브라우저 데이터를 지우거나 다른 기기를 쓰면 재투표가 가능합니다. `예상 투표 인원` 자동 마감으로 총 표 수를 제한할 수 있습니다.
- 세션 토큰은 서버 메모리에 보관 → 서버 재시작 시 관리자는 다시 로그인하면 됩니다(투표 데이터는 파일에 안전).
- HTTPS는 호스팅 업체(또는 앞단 Nginx)가 처리한다고 가정합니다.
